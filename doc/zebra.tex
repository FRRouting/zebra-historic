\section{What is zebra}

\subsection{overview}
  現在 TCP/IP を利用できない地域はほとんどありません。また、The Internet が
カバーする地域も Network の発展に伴い拡大する一方です。

  もしあなたが現実に TCP/IP を利用して LAN を構築する場合や、 The Internet 
に接続するといった時に必ず問題となるのが経路制御と言えます。もちろん、それ以
外にも様々な問題があることは自明ですが、まず相手との通信を確立するために経路
制御が非常に重要な要素である事は論をまちません。

  \zebra は、この最も重要な要素である経路制御を行うための一連の software の
集合体です。そして、この最も大きな特徴は Public Software として一般に流布さ
れているということです。


  \zebra には以下のような Routing Protocol Daemon と、それを利用するための
tool や daemon を提供します。


\begin{itemize}
  \item zebra\\ 
  \zebra は、以下に挙げる各種 Routing Daemon から経路情報を受け取り、全ての
経路情報を Merge して kernel に転送する機能を受け持ちます。

  \item ripd\\
  \ripd は 小規模 LAN でしばしば利用される {\it RIP} による経路情報を受け取
り、自身の持つ経路情報を広報する機能を受け持ちます。\\

  \ripd は {\it RIP version 1} と {\it RIP version 2} の両方の経路制御
情報を扱う事が出来ます。

  \item ripngd\\
  \ripngd は、IPv6 による経路制御プロトコルである {\it RIPng} による経路情報
を扱う事が出来ます。

  \item ospfd\\
  \ospfd では、大規模 LAN 等でしばしば利用される {\it OSPF} による経路情報を
扱うことを目指しています。現在 \ospfd は公開されておらず、将来の release に
組み込むべく作業が続けられております。

  \item bgpd (RFC1771)\\
  \bgpd は Exterier Gateway 間で利用される {\it BGP} による経路制御情報を扱
うための program です。\bgpd はまた、{\it BGP4+} の経路制御情報をも扱う事が
出来ます。

\end{itemize}

\section{Installation}

  program の compile には{\it GNU C Compiler} が必要です。

  \zebra の package を持って来て展開した後、

\begin{screen}
\begin{verbatim}
% ./configure
% make
% su
# make install
\end{verbatim}
\end{screen}

  で Install されます。その後、必要ならば {\it /etc/services} に以下の情報を
加えて下さい。

\begin{boxnote}
\begin{verbatim}
zebrasrv      2600/tcp            # zebra service
zebra         2601/tcp            # zebra vty
ripd          2602/tcp            # RIPd vty
ripngd        2603/tcp            # RIPngd vty
ospfd         2604/tcp            # OSPFd vty
bgpd          2605/tcp            # BGPd vty
\end{verbatim}
\end{boxnote}

\section{Introduction}

  \zebra system は Routing Engine として \ripd,\ripngd,\ospfd,\bgpd
を、Routing Engine 間及び Routing Engine と kernel の仲立ちとして
\zebra を提供します。

  各 Routing Engine が独立で自身の経路情報を維持し、\zebra は全ての経路情報の
和集合の経路を保持します。したがって、各 Routing Engine を切り離してもその他
の Engine に対して最小限の影響しか与えません。

\begin{figure}
\input{archfig}
\end{figure}

  \zebra は multi-thred OS を使用している場合には multi-thred で動作し
ます。特に GNU hurd で thred を利用して動作させるべく現在開発しています。

  GNU hurd 上では\zebra が routing selection メカニズムを提供します。

  \bgpd は Route Server や Route Reflector としても動作させる事が出来ま
す。\bgpd では BGP4 の update や withdraw メッセージを dump できます。
\bgpd を Route Server もしくは Route Reflector として動作させる際には、
\bgpd のみ起動していればよく、\zebra や \ripd,\ospfd,\ripngd 等は動作させる
必要はありません。

  Routing Engine が独立している事で、このような事を自在に行えるようになって
います。

Configration File
*****************

   Each daemon has a configuration file.  For example zebra's default
configuration file name is 'zebra.conf'.  Program name plus '.conf' is
default configuration file name. You can specify configration file by -f
or -config-file option to the daemon.

   In configuration file, you can write debug option, vty's password,
routing daemon configuration, logfile name and so on.

Sample Configuration
====================

   Below is sample configuration of zebra daemon.

     !
     ! Zebra configration file
     !
     password zebra
     enable password zebra
     !
     logfile zebra.log # logfile name

   '!' and '#' are comment character.  If the first character of the
word is one of comment character, from the character to the end of line
is ignored as commecnt.

     password zebra!password

   If comment character is not the first character of the word, it's a
normal character. So above '!' doesn't regard as comment and password is
set to 'zebra!password'.

RIPngd
******

   RIPngd supports RIPng protocol which described in RFC2080.  It's IPv6
reincarnation version of RIP protocol.

   Currently RIPngd supports following commands.

     interface IFNAME
      describe DESCRIPTION
      ripng receive
      no ripng receive
      ripng send
      no ripng send
     
     router ripng
      flush_timer TIME
      aggregate IPV6ADDR/PREFLEN
      network IPV6ADDR/PREFLEN

Linux netlink
*************

   On recent Linux kernels, there is a kernel/user communication support
which called netlink.  It can possible asyncronous communication between
kernel and zebra such as routing socket over BSD systems.

   Before you use this feature, you will need add Networking options of
'Kernel/User network link driver' and 'Routing messages'.

   And also you will need to create /dev/route spectial device file by
calling:

   # cd /dev # ./MAKEDEV route

   To confirm this file, please ls it.

   # ls -l route crw-rw---   1 root     sys       36,   0 Nov 25 02:36
route

   After doing this, please reconfigure and make install zebra.  You can
use it as dynamic routing update channel between zebra and kernel.
